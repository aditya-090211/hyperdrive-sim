# HYPERDRIVE simulator audit — 31 October 2026

Update: local fixes have been implemented for the findings below. Browser regression
checks passed for invalid input, bounded actions, alliance authorization, sender
signatures, replay protection, menu fit, camera rotation, clock progression and full
match completion. Malformed C++ now returns an error. PostgreSQL regression checks
passed for the score-verification migration and robust statistics. The original
findings below describe the pre-fix version. On 1 November 2026, the updated site
was deployed to https://hyperdrive-sim.vercel.app and `supabase/hardening.sql` was
applied to the production database. Live checks confirmed score-verification
permissions and robust statistics. A two-browser production test passed room
creation, guest joining, seat selection, remote driving and state mirroring through
the relay connection, with no captured page errors. Late seat input, stale result
dialogs, scoreboard keyboard shortcuts and below-floor recovery were also fixed.

Scope: local working copy, Chrome headless, six viewport sizes, keyboard driving, pause/resume, accelerated full match, isolated network-message probes, isolated malformed C++ compilation, and source review. No production account, database, or other player's room was modified. Production deployment parity and deployed database policies were not verified. This is not proof that every bug has been found.

## High priority

1. **Malformed C++ can hang compilation and freeze the application. Reproduced in an isolated worker.** Import a `.cpp` containing `using namespace std` without a terminating semicolon. Compilation failed to return within 1.5 seconds; `cpp.js:411` loops until `;` without checking EOF, while `next()` continues returning EOF. `auto.js:53` compiles synchronously on the UI thread, so the normal import path can freeze the page. Add EOF checks to all delimiter-scanning loops and compile in a worker with a time and input-size limit.

2. **Leaderboard scores are client-authored and forgeable under the supplied schema. Source confirmed; no production submission attempted.** `account.js:150–163` inserts scores directly. `supabase/schema.sql` grants authenticated users INSERT on their own matches, validating ranges rather than completed gameplay. A user can insert a 5000-point result, choose arbitrary ranking points, and have it consumed by `leaderboard()`. Verify matches in a trusted service or clearly separate unverified scores from competitive rankings.

3. **Guests accept control messages from a non-host sender. Reproduced in isolated Online instances.** `online.js:onMsg` does not verify `from === room.hostId` on its guest branch. A test call from `attacker` with `{t:'menu'}` invoked the guest's menu hook. `net.js:onRelay` forwards broadcast payloads without authenticating their claimed `from`; `onSignal` also accepts a host announcement. Room knowledge is therefore insufficient protection against impersonation. Authenticate senders, verify the designated host, and authorize channel membership. A complete live relay attack was not performed.

4. **One input packet can cause excessive synchronous actuator work on the host. Reproduced.** After establishing an applied gripper counter of zero, a valid seat-owner packet with counter 10000 caused exactly 10000 `toggleGrip()` calls in one `applyRemote()` invocation. The packet format permits larger signed integers. `online.js:applyRemote` loops until it reaches the client-supplied counter. Validate monotonic safe counters and cap actionable deltas per update; resynchronize without replaying unlimited historical actions.

5. **Malformed network inputs throw exceptions. Reproduced.** A seat-owner message with `s:[null]` throws `Cannot read properties of null (reading '0')` in `online.js:onMsg`. Invalid payload robot IDs also reach `game.js:payloadAction`, which dereferences the missing payload. Validate each message and nested tuple before dispatch; isolate errors so a bad packet is dropped. An exception was demonstrated, not permanent host failure.

6. **Human Player payload requests can target the other alliance. Reproduced at dispatch; actual game effect established by source.** A red seat owner sending `sq:'red', a:'pl', r:2` passed authorization and dispatched a request for Blue 1. `main.js:doHp` ignores squad for payload actions; `game.js:payloadAction` uses the supplied robot's squad. Validate that the requested robot exists and belongs to the authorized alliance before any action.

## Medium priority

7. **Client-controlled sequence numbers can poison later input handling. Source confirmed.** `online.js:onMsg` checks an older sequence against `m.n` without requiring a finite safe integer or enforcing bounded forward progress. A huge sequence suppresses future normal packets until a session/input reset; malformed counter values can similarly interfere with actuator edge tracking. Require finite integers and bounded progression. This was reviewed in source rather than tested through a live connection.

8. **Main menu falls below short viewports. Reproduced; scrollable, not permanently inaccessible.** At 844×390, Learn to play, account creation, and Privacy begin below the viewport; menu content is 505 px tall. At 1920×400, the Online/Practice/Robot code buttons extend below the viewport and total content is 531 px tall. The current CSS already enables menu scrolling, so this does not reproduce an unscrollable menu. Add height-sensitive spacing/type sizing and a clear scrolling affordance. Normal 1366×768, 1024×600, 390×844, and 320×568 had no menu-control bounding boxes outside the viewport. Screenshots are stored in the workspace root.

9. **Changing orientation leaves the driver camera's field of view stale. Source confirmed.** `main.js:setCamera` chooses an 80° lens in portrait, but resize handling only updates aspect and renderer size. Rotating/resizing after choosing a camera retains the old portrait/landscape lens until the camera is selected again. Reapply the active camera's orientation-dependent FOV on resize without unnecessarily resetting its position.

10. **Match time slows under sustained low frame rates or stalls. Source confirmed.** `main.js:frame` caps elapsed time to 0.05 s; simulation also discards accumulated time at MAX_STEPS. At a sustained 10 FPS, at most 0.5 simulated seconds pass per wall-clock second. The 2:30 match can last roughly five real minutes, and background-host stalls lose time too. Decide explicitly whether match duration is wall-clock or simulation time; for a timed competitive match, keep the authoritative deadline independent of physics catch-up.

11. **Writable match details can break personal statistics. Source confirmed under supplied schema.** The schema permits arbitrary size-limited `details` JSON, while `my_stats()` casts `red_maps`, `blue_maps`, and `balances` directly to integers. An otherwise allowed own-match insert with `details.balances = 'bad'` causes the stats query to fail; oversized integer strings can overflow. Validate JSON types and ranges on insertion and make aggregation robust to old malformed data. No database write attempted.

## Checks that passed and limits

- Local application boot completed without captured page errors in the initial run.
- Keyboard driving moved Red 1 forward; Escape paused the game and opened its menu after allowing a frame for processing.
- Accelerating a complete match reached `final` at exactly 150 simulated seconds, with finite robot positions and a 0–0 tie awarding one RP each.
- Isolated network probes did not contact other rooms or mutate live account data.
- C++ hangs were contained in a disposable worker.
- Full scoring-rule conformance, advanced ring stacking, Apex reachability, real touch devices/controllers, cross-browser behavior, real multi-client latency/reconnect, authenticated account flows and production database policies remain untested. README-documented limitations are not independently confirmed bugs.
